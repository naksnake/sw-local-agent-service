# Where the model weights come from, for scripts/fetch_models.py on a CONNECTED host.
# One line per model:  <path> <owner/repo> [revision]   # a trailing comment is allowed
#   <path> is the directory name under Models/ and the `path` field in Models/models.yaml
#   (config/models.quickstart.yaml and config/models.prod.yaml name exactly these paths).
#   [revision] pins a branch, tag or commit; every line below pins the commit that was
#   current on 2026-09-16, so a fetch is reproducible and a silent upstream change is not
#   picked up. Move a pin on purpose, then update vram_gib in the registry if the size moved;
#   the fetch re-downloads every changed file, small ones included, and install.sh refuses to
#   mix the old and the new revision under Models/.
# The running platform never downloads anything (INV-1). The fetch normally runs on a separate
# build host; running it on the platform host before it is installed is CLAUDE.md §15 open
# decision (13).
#
# Sections name the install profile that needs the models below them (CLAUDE.md §3):
#   `--profile quickstart` fetches the [quickstart] lines; `--profile prod` fetches both.
# Sizes are what the script downloads after skipping the formats vLLM never reads (ONNX,
# TensorFlow, Flax, Rust and Lightning files, and PyTorch pickles when safetensors exist).
#
#   scripts/fetch_models.py fetch --sources config/model-sources.txt --profile quickstart --dry-run --dest ./models
#   scripts/fetch_models.py fetch --sources config/model-sources.txt --profile quickstart --dest ./models
#   ./install.sh --models ./models          # on the platform host: verify, place under Models/, write models.yaml
#   ./install.sh --models ./models --models-only   # the same before the bundle exists
